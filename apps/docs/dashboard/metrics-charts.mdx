# Metrics and charts

![Metrics dashboard](/images/product/dashboard-metrics.png)

Metrics views are optimized for asking, "what happened to this metric across
the selected runs?"

## Metric catalog

The metric catalog groups available metric keys by namespace, coverage, point
count, goal-aware best value, and selected-run presence.

Use namespaces such as `train/`, `eval/`, `reward/`, and `system/` to keep the
catalog readable.

## Chart controls

Current chart controls include:

- Selected metric.
- Step or logged-time x-axis.
- Optional smoothing.
- Grouped averages.
- Group by seed, first tag, or the current fixed config grouping options such
  as `algo` and `policy`.
- Range brush zoom.
- Hover readouts with run name, metric, step, and value.
- Chart CSV export for the plotted sample.
- Chart image export for the visible graph.

Unit-bounded metrics such as accuracy, F1, precision, recall, and AUC use a
normalized `0..1` y-axis. Return, reward, and loss metrics auto-scale.

## Export chart evidence

Use the chart export buttons when you need to move evidence into a notebook,
issue, report, or lab note. CSV export contains the already plotted data,
including the visible sample, grouping labels, series type, source run count for
aggregates, step/time, value, and smoothed value when smoothing is active. Image
export renders the visible chart client-side without requesting additional
history.

Chart export is intentionally bounded to avoid browser jank. It is disabled
when a chart has more than 120 series or more than 20,000 plotted points. Use
the API export route when you need raw selected-run data rather than the plotted
chart sample.

## Bounded series requests

Metric series are fetched separately from run summaries. Comparison views should
request bounded series data by run, metric key, step range, time range, or
explicit point limit instead of asking the table view to load full history.

## Good metric hygiene

- Keep metric names stable across runs.
- Prefer slash namespaces.
- Log one training-loop dictionary per step instead of many tiny calls.
- Use consistent step semantics inside a project.
