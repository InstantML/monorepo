# Reports

The Reports tab turns dashboard context into persisted report documents for
experiment recaps, ablation notes, checkpoint decisions, launch notes, sweep
summaries, and teammate handoffs.

![Reports editor](/images/product/dashboard-reports-editor.png)

## What reports contain

Reports are block-based documents. Current block types include:

- Headings, paragraphs, markdown, code, horizontal rules, and callouts.
- Images.
- Panel grids with live metric charts, scalar panels, run comparers, markdown, code, and image panels.

Legacy LLM summary blocks remain readable in existing reports so older writeups
keep rendering. New reports should use narrative blocks and panel grids.

The Reports list shows every report visible to the active workspace. Opening a
report mounts the editor at `/dashboard/reports/{report_id}`.

## Editing and auto-save

The editor auto-saves title, description, visibility, and block changes through
the reports API. The toolbar shows save state, undo/redo controls, share, and
Markdown export.

Use visibility to choose the audience:

| Visibility | Meaning |
| --- | --- |
| Private | Workspace-authenticated report unless a share token exists |
| Organization | Workspace report intended for team readout |
| Public | Intended for public/shared read paths |

## Sharing and export

The Share action creates or rotates a share token and exposes a public `/r/...`
link. Export downloads a Markdown version for review, archives, or follow-up
analysis outside InstantML.

## Relationship to saved views

Saved workspace views still preserve dashboard layout and filters from Runs.
Reports are separate persisted documents. Use saved views for repeatable
dashboard state, and use reports when the result needs narrative context,
charts, evidence, and a shareable readout.
