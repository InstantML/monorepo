# Artifacts, files, and media

Artifacts connect metric behavior to the files and evidence produced by a run.
Use them for uploaded files, external references, checkpoints, rollouts,
versioned model collections, and the rich objects that make a training run
inspectable after the fact.

## Artifact workspace

![Artifacts workspace](/images/product/dashboard-artifacts-browser.png)

The Artifacts tab starts with versioned artifact collections for the active
project. The collection list stays separate from the selected version detail so
the main workflow is stable: choose a collection, inspect its versions, then
open the manifest and lineage for the selected version.

Each collection shows versions with stable `vN` labels, automatic `latest`,
custom aliases such as `best`, byte/file counts, retention state, and soft
delete state. Selecting a version shows its manifest and a bounded lineage view
of producer and consumer runs.

Versioned artifacts can represent:

- Uploaded files.
- External file references.
- Checkpoints.
- Rollouts.

Owner/admin users can move the `best` alias, keep a version forever, apply a
30-day retention window, or soft-delete a version after an explicit confirmation
prompt with an audit reason. Read-only users see the same evidence with
management controls disabled.

## Run Detail files explorer

![Run Detail files evidence](/images/product/dashboard-artifacts-evidence.png)

Run Detail includes a Files section for the selected run. It groups checkpoints,
media and rich objects, and files, then opens a bounded preview beside the
evidence rail.

The Files section previews:

- Tables with capped rows and columns.
- Histograms.
- Binary classification evaluation bundles with PR/ROC curves, confusion
  matrices, per-class metrics, and optional prediction previews.
- Same-origin image, audio, and video artifacts when bytes are stored through
  InstantML.
- Artifact metadata for checkpoints, uploaded files, rollout files, and
  external references.
- Copyable object or artifact IDs for SDK/API follow-up work.

Hidden Run Detail sections do not fetch object manifests until opened, so the
normal metric summary path stays lightweight.

## Raw run artifacts

Versioned collections are the primary Artifacts tab workflow. Legacy raw run
artifacts remain available so existing file/media, rich-object, checkpoint, and
importer workflows keep their old IDs and Run Detail behavior. Imported
external artifact references are also mirrored into metadata-only versioned
run-level bundles, which lets migrated W&B/Neptune/MLflow artifacts appear in
the catalog and lineage graph without copying bytes into InstantML storage.

## Safe previews

Same-origin image, audio, and video artifacts can preview in Run Detail and
Compare when bytes are stored through InstantML. Unsupported or external-only
artifacts fall back to metadata, copy, or unavailable-download actions. Stored
bytes are served through
`/api/artifacts/{artifact_id}/download`; public artifact rows expose opaque
InstantML URIs rather than raw object-store URLs.

Rich media objects can link to artifact bytes from the same run. Metadata-only
objects and artifacts remain inspectable, but they cannot be downloaded through
the same-origin route until bytes are uploaded to InstantML.

## Checkpoint forks

Checkpoint artifacts are visible in Run Detail and in the Checkpoints
workspace. They can carry restore metadata such as source run and step. When
checkpoint bytes are stored through the API, downloads go through the
same-origin artifact download route.

![Checkpoint fork modal](/images/product/dashboard-checkpoint-fork.png)

Forking a checkpoint creates a linked child run record in the same project. It
records provenance and can inherit the source config, but it does not start
training or copy metrics/artifacts. Attach the SDK to the new child run from the
training script that resumes the checkpoint.

## Checkpoint lineage

![Checkpoint lineage workspace](/images/product/dashboard-checkpoints.png)

The Checkpoints workspace gives the same selected-run context a lineage-first
view. Use it to confirm the checkpoint URI, step, run config context, and
whether a run has forkable restore points before moving into a resumed
experiment.

## API snippets

The Artifacts tab exposes copyable artifact IDs and safe download states. The
API tab exposes copyable route snippets so a user can fetch artifacts or inspect
API behavior without digging through browser network panels.
