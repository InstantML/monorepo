# Query runs and download artifacts

Most training scripts only write data. Use `im.Api(...)` when a script or
notebook needs to query runs, export data, or restore artifacts.

## Create an API helper

```python
import instantml as im

api = im.Api(
    base_url="https://api.instantml.ai",
    api_key="instantml_...",
)
```

The key needs a read scope such as `export:read` for tenant read routes.

## List run summaries

```python
page = api.runs(
    project="cartpole",
    q="seed 13",
    sort_by="metric-best",
    metric_key="eval/return_mean",
    limit=25,
)
```

Accepted filters:

| Parameter | Meaning |
| --- | --- |
| `project` | Project name. Omit or use `all` for all projects. |
| `project_id` | Legacy SDK compatibility parameter. Rust-hosted run summaries do not expose it as a query filter; use `project` or a project-scoped API key. |
| `status` | `running`, `finished`, `failed`, or `all`. |
| `q` | Shared run search query. Bare text remains implicit `AND`; field filters, exact tags/status, ID prefixes, uppercase booleans, phrases, grouping, field/group exclusion such as `-tag:debug`, and explicit Rust `re:/.../` regex are supported. |
| `sort_by` | `created`, `name`, `status`, `duration`, `metric-latest`, or `metric-best`. |
| `metric_key` | Metric used for metric sorts. |
| `limit` | Page size. |
| `cursor` | Cursor returned by the previous page. |
| `offset` | Offset pagination for compatibility paths. |

Do not combine `cursor` with a nonzero `offset`; the helper raises
`ValueError`.

Useful `q` examples:

```text
seed 13
tag:baseline status:finished
name:"long context" -tag:debug
(tag:baseline OR tag:candidate) notes:ablated
re:/seed-(13|14)/
```

## Download artifact bytes

```python
path = api.download_artifact(
    "artifact-id",
    "checkpoints/policy.pt",
)
print(path)
```

The helper creates parent directories and returns the written path. It is the
same restore primitive used by checkpoint resume snippets in the dashboard.

## Bounded reads

InstantML keeps list and series reads bounded:

- Run summary pages default to 100 rows.
- Raw metric history is requested through metric-specific series endpoints.
- Artifact lists are capped.
- Export responses include truncation metadata when limits are hit.

If you need a bulk data movement path, use export or an importer/exporter flow
instead of repeatedly fetching every chart series from a notebook.

## Existing-run writes

Use `im.attach_run(...)` when a resume script should continue logging into an
existing run, such as a checkpoint fork created by the dashboard or
`Api.fork_run(...)`.

```python
run = im.attach_run("child-run-id")
run.log({"train/loss": 0.1}, step=1001)
run.finish()
```

By default, `attach_run(validate=True)` reads `/runs/:id` before returning a run
handle. That validation needs read access such as `export:read`. Use
`validate=False` only for intentionally write-only credentials or offline attach
flows.
