Production guardrails

Focused on compatibility, privacy, and bounded control writes.

1Export strips `org_id`, `owner_user_id`, API-key data, raw tenant routes, and browser-local storage keys.
2Import ignores embedded IDs, sanitizes payloads, validates object shape and byte limits, then writes a fresh row for the current browser user.
3Replace and delete require expected_updated_at so a stale tab cannot overwrite or resurrect a newer view.
4Existing `POST` and `PUT` bodies keep accepting `{ name, project, payload }` so old dashboard builds remain compatible.
5Import dry run performs no tenant/data-plane calls; stale-run checks are client-side previews from loaded summaries.
6`/api/workspace-view-data` is read-only, accepts API keys with export:read, and returns bounded panel data without artifact bytes.
